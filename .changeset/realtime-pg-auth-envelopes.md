Seal Realtime queries with Postgres credentials instead of the Realtime secret. `createRealtime({ databaseUrl, url })` seals each query into an HPKE (P-256) envelope addressed to the branch's public key, carrying the connection string's user and password; Realtime checks them with a Postgres login. With no password in `databaseUrl`, the credential is an OIDC token, by default Vercel's runtime token, or one from `oidcToken`. Only `neondb_owner` is supported for now. The SDK fetches the branch key from `/.well-known/neon-realtime-keys` on the Realtime host and caches it for up to 10 minutes. `createRealtime({ secret, db })` keeps working. To migrate, pass `databaseUrl` and `secret` together: the SDK seals envelopes for branches that publish a key, and uses the secret for branches whose Realtime server predates envelopes (the keys endpoint answers 400 or 404) or that list no key yet, rechecking within a minute. A network error or server error never falls back to the secret, and neither does a failed envelope. The browser client accepts the new envelopes. `fetchRealtimeKey()` and `sealRealtimeEnvelope()` are low-level helpers for tooling and tests, and the v3 envelope schema is exported as `@neon/realtime/schema/realtime-query-capability-v3.schema.json`.
